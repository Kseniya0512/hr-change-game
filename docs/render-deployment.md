# Как получить ссылку на игру через Render

## Бесплатное демо для просмотра

В корне репозитория подготовлен `render.yaml`: один бесплатный Node-сервер, интерфейс, Socket.IO, автоматическая HTTPS-ссылка и случайный ключ ведущего. Платный ресурс по этому файлу не создаётся. Автоматическое развёртывание новых коммитов отключено.

Демо сохраняет планы, пока работает текущий экземпляр сервера. Бесплатная файловая система Render временная: после остановки, перезапуска или нового развёртывания можно потерять сессии и планы. Для рабочего воркшопа используйте постоянный диск, описанный ниже. Бесплатный сервер также может запускаться с задержкой после простоя.

### 1. Подключите GitHub

Откройте https://dashboard.render.com/ и зарегистрируйтесь через GitHub. При запросе доступа разрешите Render читать репозиторий `Kseniya0512/hr-change-game`.

Пароли, ключи GitHub и платёжные данные в чат не отправляются. Авторизация выполняется на сайтах GitHub и Render.

### 2. Создайте Blueprint

В Render выберите **New → Blueprint**, затем репозиторий **hr-change-game** и ветку **feat/change-workshop**. Путь к файлу — **render.yaml**. Если показан выбор тарифа, убедитесь, что выбран **Free**.

Проверьте список создаваемых ресурсов: один сервис `hr-change-game-demo`, без постоянного диска и платных баз. Подтвердите создание и дождитесь статуса **Live**. Не выбирайте `main`: готовая игра находится в ветке `feat/change-workshop`.

После развёртывания Render покажет HTTPS-адрес сервиса с доменом `onrender.com`. Это и будет ссылка на саму игру. Пришлите её в чат — по ней можно проверить реальное подключение и синхронизацию. До статуса Live существование этой ссылки и запуск игры не подтверждены.

### 3. Войдите как ведущий

На странице сервиса Render откройте **Environment**, найдите автоматически созданную переменную **HOST_ACCESS_KEY** и посмотрите её значение. На странице игры выберите **Я ведущий** и введите ключ. Значение ключа остаётся у вас.

Создайте сессию, сохраните свою ссылку ведущего и передайте участникам коды команд. Капитанам и кураторам выдаются отдельные ссылки.

## Постоянное хранение для воркшопа

Подготовлен отдельный файл `deploy/render-persistent.yaml`. Он описывает один сервис тарифа **Starter** и постоянный диск 1 GB в `/var/data`. Это платный вариант; актуальную стоимость показывает Render перед подтверждением. В этой задаче платный сервис не создавался.

Выберите этот путь Blueprint либо настройте уже созданный сервис: тариф с поддержкой диска, диск 1 GB в `/var/data`, `DATA_DIR=/var/data`. Одна активная копия сервера. При переходе с временного демо предварительно экспортируйте результаты команд: смена каталога данных сама по себе не переносит SQLite.

Для проверки постоянного хранения создайте пробную сессию, сохраните ответ, перезапустите сервис в Render и убедитесь, что действуют прежняя ссылка входа и сохранённый ответ. Также проведите короткую репетицию с капитаном и участником в разных браузерах.

## Если требуется ручная настройка сервиса

| Поле Render | Значение |
|---|---|
| Runtime | Node |
| Branch | feat/change-workshop |
| Build Command | `npm ci --include=dev --no-audit --no-fund && npm run build` |
| Start Command | `npm start` |
| Health Check Path | `/api/health` |
| NODE_VERSION | `24` |
| NODE_ENV | `production` |
| TRUST_PROXY | `1` |
| DATA_DIR | `.data` для демо; `/var/data` для постоянного диска |
| HOST_ACCESS_KEY | Сгенерированный случайный ключ, минимум 24 символа |

Render передаёт `PORT` автоматически. Сервер уже слушает все интерфейсы и использует этот порт. В сборку явно включены dev-зависимости, потому что они нужны Vite; рабочий сервер запускается обычным `npm start`.

Справка Render: https://render.com/docs/blueprint-spec, https://render.com/docs/free, https://render.com/docs/disks. Базовые поля Blueprint сверены с официальным примером https://github.com/render-examples/express-hello-world. Точный текущий тариф и успешное создание ресурсов подтверждаются в аккаунте Render.
