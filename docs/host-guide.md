# Руководство ведущего

## Запуск

Нужны Node.js 24+, постоянный диск и один процесс приложения. Из корня проекта:

```bash
npm ci
npm run build
npm start
```

Порт по умолчанию — 3000. Для изменения параметров используйте переменные окружения или скопируйте `.env.example` в `.env`. Файл `.env` для запуска не требуется.

Первый запуск создаёт локальный ключ ведущего в `.data/host-key` с ограниченными правами доступа. Посмотрите этот файл локально и введите ключ на странице «Я ведущий». Значение не записывается в логи. На хостинге можно задать собственный случайный `HOST_ACCESS_KEY` длиной не менее 24 символов через защищённые настройки.

## До встречи

1. Создайте сессию: название, 2 или 3 команды, продолжительность (по умолчанию 30 минут).
2. Сохраните свою ссылку ведущего. Код команды даёт только роль участника; отдельные ссылки капитана и куратора передайте назначенным людям.
3. Назначьте кейсы до начала. Все команды могут решать один кейс, либо разные команды — разные кейсы.
4. При необходимости отредактируйте «Материалы и подсказки». Действующие и приостановленные раунды защищены от изменения материалов.
5. Подготовьте комнаты в Microsoft Teams. Игра не создаёт комнаты и не отправляет сообщения в Teams или живому ЦЭИ.

Для проверки нескольких ролей на одном компьютере используйте разные профили или отдельные контексты браузера: в одном профиле вкладки используют один вход.

## Во время раунда

- «Начать всем» запускает общий отсчёт. Также можно запускать команды отдельно.
- Участники отправляют предложения. Капитан или куратор фиксирует общий ответ кнопкой «Зафиксировать блок».
- «Принять к работе» отмечает предложение как принятое к обсуждению; содержательное решение нужно внести в соответствующий блок.
- Все видят подтверждённые ответы сервера. Изменения без фиксации — черновик автора. Он сохраняется при переходах между экранами в текущей вкладке; при обновлении страницы браузер предупреждает о несохранённом вводе.
- При конфликте двух редакторов приложение показывает актуальный ответ и предлагает явно выбрать, какой вариант сохранить.
- Можно поставить паузу, продолжить или добавить 5 минут. Завершённый раунд можно продлить; он откроется на паузе, затем нажмите «Продолжить».
- По умолчанию событие открывается за 7 минут до окончания. Ведущий может открыть его раньше. Куратор может записать обоснование альтернативного решения.
- В действиях, коммуникациях и собственных рисках доступен необязательный пункт «Связать с рисками». Он помогает найти подготовленный ответ на неожиданное событие. Для действий нужны текст, владелец и момент; для коммуникаций — также аудитория и канал; для рисков — причина, последствие, профилактика и реакция. Связь не добавляет обязательных согласований и не оценивает качество решения.
- Автоматическое событие выбирается прежде всего из ситуаций без связанного заполненного ответа. Если все ситуации учтены, игра предлагает событие по выбранному риску либо первое событие кейса. Текст ответов не интерпретируется. Если команда предусмотрела решение иначе, она может показать его куратору.
- Индикатор заполненности и обращения к помощи предназначены для обсуждения; баллов и рейтинга нет.

## После раунда

Скачайте PDF каждой команды. Незавершённые разделы помечаются явно. Вопросы для ЦЭИ и реакция на событие входят в результат. Кнопка «Следующий кейс» создаёт новый раунд с другим кейсом; предыдущий PDF остаётся в разделе истории команды.

Если ссылка капитана или куратора потеряна, выдайте новую в панели ведущего. Старые приглашения и входы этой роли в команде будут отозваны. Код участника остаётся прежним.

## Размещение для участников

Для проведения встречи нужен публичный HTTPS-адрес сервера, доступный участникам, с поддержкой WebSocket/Socket.IO и постоянного диска. Один процесс Node обслуживает интерфейс, API и обновления. GitHub Pages подходит для статических файлов и не запускает этот сервер.

Задайте `NODE_ENV=production`, `DATA_DIR` на постоянном диске и `HOST_ACCESS_KEY` в защищённых настройках. Если перед сервером один доверенный reverse proxy, задайте `TRUST_PROXY=1`. Сохраняйте исходный Host и передавайте соединения Socket.IO. Куки при production требуют HTTPS.

В этой версии предполагается одна активная копия сервера. Резервное копирование SQLite выполняйте штатными средствами SQLite или при остановленном процессе, сохраняя весь каталог данных. Развёртывание на внешнем хостинге в рамках реализации не выполнялось.

## Методологические решения

Используются 8 критериев слайда 6 презентации старта пилота, порог 2+ «да» согласован организатором. Неизвестные ответы не считаются отрицательными. Числовая граница охвата «20–30+» не превращена в автоматическую проверку. Чемпионы — по необходимости, спонсор выбирается по полномочиям, ресурсам и приверженности.

Исходные PDF, PPTX и HTML сохранены. Статические объяснения содержат ссылки на страницы/слайды; корпоративные имена в игровые кандидаты не переносятся. В кейсе премирования отсутствующие бизнес-причина и база процентов остаются вопросами к инициатору. Сохранение бюджета льгот не считается равноценностью ДМС и возмещения.

## Материалы и совместимость

В редакторе ведущего у каждого события можно выбрать связанные риски кейса. Изменение формулировок сохраняет эти связи. Правки действуют по существующим правилам версий: текущий запущенный раунд и история не переписываются.

Старые раунды без связей остаются доступны, сохраняются и экспортируются. Игра не угадывает связи по их тексту: для таких материалов автоматический выбор использует первое событие, а ведущий может выбрать другое вручную. Новые сессии используют обновлённые шаблоны; существующие сессии сохраняют свою версию до редактирования организатором.

По решению организатора от 13 ноября работа ведётся только в `hr-change-game`, ветка `feat/change-workshop`; интеграция с опросами в эту доработку не входит.
